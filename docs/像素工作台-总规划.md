### D12（待做，晚上执行）：鱼可以被拖拽

> 用户 m02537 原话：「每条鱼可以被从工位拖到任意位置，拖到办公室区域中别的位置后会懵逼1秒，头上冒出问号，然后走回原来的工位，拖到屏幕任意位置也是懵逼1秒，冒问号，但是会先走到门口，然后进去，再走到工位上」

设计要点（已定，未实现）：
1. **命中检测**：canvas 上按角色 sprite bbox 反查 seatId（`drawActors` 里已算出每人的 `x/y/w/h`，抽成 `hitTest(clientX, clientY)` 即可）。层级取 z-order 最上者。
2. **拖拽中**：角色脱离座位，跟随指针（换算成场景逻辑坐标），播放 `poseThinking` 之前的普通站姿；原工位置 `EMPTY`（屏幕立刻灭）。
3. **放下判定**：
   - 落在**办公室区域**（canvas 内且不在原座位）→ 原地懵逼 1 秒（头顶问号，抖动 2 次）→ 用 `planPath()` 从落点走回原工位 → 坐下、屏幕重新点亮。
   - 落在**办公室区域之外**（拖出 canvas / 拖到页面别处）→ 懵逼 1 秒 → 先走/瞬移到门口 → 走出画面 → 再从门走回原工位。
4. **问号气泡**：复用气泡 DOM，内容固定为 `?`，`bubble` 加 `kind:'emote'` 以免被 assistant 文字覆盖；1 秒后自动清。
5. **状态机扩展**：`SEATED_IDLE` 增边 `→ GRABBED`（指针按下）→ `CONFUSED`(1s) → `WALK_HOME` / `EXIT_AND_REENTER` → `SETTLE`。座位加 `lockedByDrag` 时间戳，期间 `applySnapshot()` 不覆盖位置。
6. **收尾约束**：拖拽期间不打断 Host 数据，`activity` 照常更新（气泡照常出字），只是位置被拖走；松手归位后一切复原。


### D13（本轮主线，m02609 + m02671）：拖拽 / 双击三级互动 / 空格彩蛋

> 用户 m02609 原话见对话记录；m02671 追加硬约束：**「头上冒出的东西不要用ai绘图」**——问号、爱心、🤓👆🏻、😡、Z 这类头顶符号一律用**代码绘制**（canvas 手写像素点阵），或用 DOM 里的 emoji 文本，绝不走 AI 生图。

#### D13.1 朝向系统（一切互动的地基）

每个角色有 3 个朝向，各需要一组坐姿帧：

| 朝向 | 代号 | 用途 | 主角资产 | 副角资产 |
|---|---|---|---|---|
| 背面（背对观众，看后脑勺） | `back` | 默认工作态 | `main-sit-*` / `main-type-*` | `mN-*-sit.png`（已有） |
| 正面（面对观众） | `front` | 双击互动、掉落 | **待生成** `main-front-*` | 待生成 `mN-*-front.png` |
| 侧面（90°，朝右；朝左靠镜像） | `side` | 走向门口、排队右行 | **待生成** `main-side-*` | 待生成 `mN-*-side.png` |

**转身动画**不做逐帧过渡资产，用代码合成：

- `back ↔ side`：以脚底为支点，横向 `scaleX` 从 `1 → 0.55` 并同步把同一张图按 1px 台阶横向错位（3 阶），最后切 `side` 帧。S 形错觉，160ms。
- `side ↔ front`：`scaleX` 从 `0.55 → 1`，切 `front` 帧，160ms。
- 合起来 `back → front` = 两段 320ms，中途插一张 `side` 帧，读感就是"转过身"。
- 实现为 `turnState[seatId] = { t0, from, to }`，`drawActor()` 里按 `progress` 调 `drawTurnFrame()`。

#### D13.2 拖拽（扩展 D12）

命中检测 `hitTest(clientX, clientY)`：把客户端坐标换回场景逻辑坐标，反查每个在座角色的 sprite bbox，**取 z-order 最上者**（与 `drawActors()` 的排序一致）。

状态机（每个角色一份）：

```
SEATED(back|front|side) ──pointerdown──> GRABBED ──pointerup──> CONFUSED(1s, ?) ─> WALK_HOME | EXIT_AND_REENTER ─> SEATED(back)
```

- `GRABBED`：脱座跟随指针，原座位屏幕立刻灭（`seat.lockedByDrag = t`，`applySnapshot()` 期间不覆盖该座位位置）；角色朝向切 `front`（被拎起来面朝观众）。
- 松手判定：
  - 落点在 **canvas 内** → `CONFUSED` 1s（问号 + 抖动 2 次）→ `planPath()` 从落点走回原工位（`side` 或 `back` 按走向选）→ 坐下、屏幕复亮。
  - 落点在 **canvas 外**（屏幕任意位置）→ `CONFUSED` 1s → `side` 朝向走到门口 → 出画 → 从门 `back` 走回工位。
- 问号符号：`D13.5` 的代码点阵，不生成图片。

#### D13.3 双击三级互动（每条鱼独立计数）

`dblTick[seatId]` 0→1→2→3→回到 1（第 3 级演完复位到 0）。

| 次 | 序列 | 时长 |
|---|---|---|
| 1 | `back→front` 转身 → 头顶冒**爱心** → 停 2s → 转回 `back` | ≈2.5s |
| 2 | `back→front` → 烟雾遮住（`SMOKE`）→ 散开时**消失**（不画角色）→ 停 2s → 烟雾再起 → 散开**出现**、`front` → 头顶冒 **🤓👆🏻**（代码点阵：眼镜脸 + 食指指上）→ 停 2s → 转回 `back` | ≈5s |
| 3 | `back→front` → **原地跳 3 次**（每次 220ms，`y -= 8*sin`，落地震屏 1px）→ 落地处**裂纹**从 4px 扩到 sprite 宽（`CRACK`，480ms）→ **掉落**：角色切到"前景浮层"（`zIndex` 高于办公室底图的独立层），`front` 朝向、双手挥舞（左右交替 4 帧感的代码旋转）、`y` 加速下落到**屏幕最下方** → 触底**反弹**（`y` 回弹 22px，再落回）→ 冒 😡 → 停 2s → **双烟雾**（鱼位置 + 原工位同时）→ 2s 后同时散开，鱼回到原工位 `back` 坐姿 | ≈8s |

- 第 3 级掉落期间：**办公室面板不跟着掉**。角色进 `_poSkyLayer`（`position:fixed`、`zIndex:95`、`pointerEvents:none`），坐标用视口坐标，所以能一路掉到浏览器底部、浮在所有内容之上。
- 互动期间 `pointerEvents` 继续接受双击，但 `busy[seatId]` 标记期间忽略新的双击（防抖）。
- 双击识别：`pointerup` 时距上次 `pointerup` < 320ms 且位移 < 6px 计一次。

#### D13.4 空格彩蛋（全员出逃）

```
按住空格 + 拖拽  → 松手：不回归，就地坐下（有坐下动画 260ms：y 下沉 4px + scaleY .9→1）
                  → 待机态，间歇眨眼（每 2.4~4.8s 随机闭眼 120ms，用 front 帧 + 眼皮 2px 覆盖）

                  → 统一向右走（WALK_SPEED 同速，side 帧）
                  → 最后一个走出右边界后：
                      DSH 界面最小化（这里**不做**，改为：办公室面板整体淡出 + 遮罩）
                      屏幕中央弹出硕大木质像素告示牌（AI 生成，src=ui/board-eat.png）
                      弹出用非线性动画（elasticOut：scale 0→1.18→0.94→1 + 轻微旋转回正，620ms）
                      牌上文字「您的全体员工已出逃，无法继续工作！」—— 文字是**代码画的像素字**，不烧进图片
```

- 文字不烧进 AI 图：图只出**空白木牌**，文案用 canvas 像素字（`D13.5` 的字模）画上去，保证可读、可改、可多语言。

#### D13.5 头顶符号与特效：全部代码绘制（m02671）

新增 `tools/` 外的运行时模块，直接写进 `client.js`：

- `PIXEL_GLYPHS`：手写点阵字典，1 = 实心。
  - `?` 7×9、`heart` 9×8、`angry` 9×8、`nerd` 11×9（眼镜 + 上指食指）、`zzz` 9×6、`sweat` 5×7。
  - 调色板：黑 `#1a1526` 描边、白 `#fdf6e3` 主体、红 `#ff5470`、黄 `#ffd166`、青 `#5ee6c8`。
  - 绘制：`drawGlyph(g, name, x, y, scale)`，每格 `scale` px，先描黑边再填色，保证在深色底上看得清。
- `SMOKE`：不用图片。3 层圆团按 `t` 从中心向外扩散 + 透明度衰减，颜色 `#cfc6e0 / #a99fc0 / #7d7396`，边缘用 `fillRect` 逐块（8px 网格）画成方块团 → 天然像素感。
- `CRACK`：从落点向 5 个随机方向递进画 1px 折线，长度随 `t` 从 4px 到 sprite 宽，颜色 `#0d0a14` + 内侧 1px `#2b2136`。
- `DUST`（落地/跺地扬尘）：6 个 2×2 方块向外抛射 + 重力下坠 + 透明度衰减。
- 抖动：`shake` 计时器，`dx = sin(t/18)*2`，双层（角色 + 场景 1px 反向）读感更好。

### 为什么废弃代码直绘

代码直绘（v1→v3b）解决了两件事：3/4 斜俯视的立体画法（顶面 + 前立面 + 1px 分界）、纯色块 + 描边 + 分段明暗。但三版都过不去一个坎——**角色造型**。32×32 里靠手写 profile 数组表达"是条鱼、戴着眼镜、在敲键盘"，试了背对观众、四层剪影、扇形鳍，读出来都是一颗球。这不是参数问题，是手绘精度问题。AI 出的 `fish-main.png` 造型一次就对。

结论：**形状交给 AI，颗粒感和色板交给后处理**。后处理这条链路已经验证可行（`tools/pixelize.mjs`），而且它才是"元气骑士那种颗粒感"的真正来源。

## 1. 资产生产流水线（AI only）

### 1.1 三段参考图链：先锁形，再动起来

AI 生图跨次调用**没有记忆**。每多生成一次，形象就漂移一点。所以不能"9 个动作帧各生成一次"，必须用参考图把形象钉死。

三段链：

```
① 造型基准     fish-main.png                      ← 已存在，判定合格
                  ↓ 作参考图
② 姿态基准     坐姿正面 / 坐姿背面 / 侧面 / 走姿上 / 走姿下
                  ↓ 每个姿态作参考图
③ 动作帧       每个姿态下 2~4 帧（打字循环、走路循环）
```

**硬规则**
1. 第 ② 段的每一张，参考图都只用 ①（不用兄弟姿态作参考，避免误差串联累积）。
2. 第 ③ 段的每一张，参考图 = ① + 对应 ② 的姿态（两张，正好在 4 张上限内）。
3. 提示词里写死色值（`#2f8496` 身体、`#e8dcc8` 肚皮、`#ffd166` 呆毛），颜色漂移一半靠这个压。
4. 每段生成后**必须肉眼看**，不合格就重生成该张，不许往下传。串坏一张，后面全废。

### 1.2 单图多姿态优先（关键取舍）

跨次生成一致性差，**同一张图内**一致性最好。所以姿态基准优先让 AI 一次画成 sprite sheet，而不是分 5 次生成：

- 需求：`3×2 网格，6 个同一角色的不同姿态（正面坐姿、背面坐姿、左侧、右侧、走路上、走路下），纯品红 #FF00FF 背景，每个姿态等距格，角色居中，无阴影无地面`
- 出图后按格切分（`ffmpeg crop` 或后续写个切格脚本），得到 6 张等尺寸 sprite。
- 切出来的每张再作参考图去生动作帧。

**风险**：AI 对"等距网格"的执行力不稳定，格子对不齐、姿态画错位。所以：
- 首选方案是 sprite sheet；
- 若 2~3 次都失败，降级为逐姿态单独生成（参考图 = 造型基准 + 已确认的相邻姿态），并把这种降级在资产报告里标出来。

### 1.3 背景抠除

所有角色 sprite 用**纯品红 `#FF00FF`** 作背景生成（`fish-main.png` 已是品红底）。后处理：

```
ffmpeg -i in.png -vf "colorkey=0xFF00FF:0.18:0.05,format=rgba" out.png
```

- 用 `colorkey`（RGB 空间）不用 `chromakey`（YUV 空间），像素画边界更干净。
- 抠完必须检查边缘：像素风描边是深色，抠色阈值过大会把描边一起吃掉。阈值参数留可调。
- 兜底：若某帧抠不干净，改在该帧上手工补一圈 1px 描边（后处理脚本里加一个 `--outline` 开关）。

### 1.4 像素化与色板统一

流水线走 `tools/pixelize.mjs`：降采样（area）→ 中值滤波抹 AI 纹理 → 量化调色板（dither=none）→ 整数倍最近邻放大。

**新增要求：全场景统一色板。** 现在每张图各自 `palettegen`，不同图色板不同，叠在一起会脏。改为：

1. 场景底图 + 全部角色姿态图先各自降到目标分辨率；
2. 取一张"色板源图"（建议用拼了主色块的合成图）跑一次 `palettegen:max_colors=32:stats_mode=full`，导出 `assets/palette.png`；
3. 所有资产用 `paletteuse=dither=none` 套**同一张** palette.png。

这样才像同一个游戏里的东西。

### 1.5 分辨率与颗粒度

目标逻辑分辨率 **320×480**（场景），角色主 32×32 / 副 24×24。显示时按容器宽度取整数倍放大（`image-rendering: pixelated`）。

比之前 v3 代码直绘的 176×260 宽一倍，原因：AI 原图 1664 宽，压到 320 是 5.2 倍压缩，颗粒足够粗且细节还在；压到 176 是 9.5 倍，桌椅就糊成一团了。颗粒感的来源是**少色 + 纯色块 + 无抗锯齿**，不是把分辨率压到最低。

### 1.7 副角（子 agent）形象策略

不做每个模型一套完整动画。做法是 **一套通用骨架 + 模型化装扮层**：

1. 做 1 套**通用小人骨架**（同一套动作帧，24×24）；
2. 装扮用可替换的小部件覆盖：头发/帽子、上衣色、眼镜、耳机、工牌，都是 8×8 以内的小贴图；
3. 模型→装扮映射表（从 `agentOptions.model` / `provider` 取串，小写前缀匹配）：

| 匹配前缀 | 装扮 |
|---|---|
| `deepseek*` | 小号同族鱼，青蓝身白肚，无眼镜 |
| `claude*` / `anthropic*` | 陶土橙短发 + 白衬衫 + 圆框眼镜 |
| `gpt*` / `openai*` | 墨绿连帽衫 + 耳机 |
| `gemini*` / `google*` | 蓝黄拼色 polo + 反戴棒球帽 |
| `qwen*` / `tongyi*` | 紫卫衣 + 挂脖工牌 |
| `glm*` / `zhipu*` | 深蓝马甲 + 领带 |
| `grok*` / `xai*` | 全黑高领 + 银耳钉 |
| 未命中 | `hash(model) % 8` 落「工牌色 × 帽子 × 肤色」组合池 |

这样新增模型不用重画动画，只加一层贴图。代价是副角身形都一样，靠配色和头部件区分——在 24×24 尺度上这是合理取舍。

**屏幕矩形**也一并写进去，不要在前端算偏移（偏移量写死在代码里，底图一改就全错）：

```json
{

    "id": "main",
    "deskAnchor": [160, 96],
```

### 2.3 z-order

3/4 斜俯视不做透视矩阵，只按 `seatAnchor[1]`（y 值）从小到大排序绘制角色。y 小的先画（远），y 大的后画（近）。同一排按 x。

**注意**：动态层（光晕、屏幕）不参与 z-order 排序——它们永远画在底图之上、角色之下（屏幕光晕要盖住桌面但不能盖住人）。唯一的例外是屏幕亮条，它画在角色之前，这样人挡住屏幕时是"人挡住光"而不是"光浮在人身上"。

## 3. 入场 / 离场动画

### 3.1 状态机

每个座位一个独立状态机，状态挂在 `OfficeState.seats[i].anim`：

```
EMPTY ──agent 出现──> QUEUED ──轮到──> ENTERING ──> WALK_LANE ──> WALK_UP
                                                                    ↓
SEATED_IDLE <──SETTLE(起身/坐下过渡) <──────────────────────────────┘
     ↓ 收到工作事件
WORKING(打字循环) ──> REPORTING(气泡) ──> IDLE
     ↓ agent 结束
LEAVING ──> WALK_DOWN(反向) ──> EXITING(出画) ──> EMPTY
```

- `QUEUED`：已分配座位但还没轮到进场。视觉上工位**空着**，不放人。
- `ENTERING`：从画布外（y = h + 16）向上走进画面，走到门的横向位置。
- `WALK_LANE`：沿底部走道横向移动到本座位的 `walkLaneX`（用侧面走姿，左右镜像）。
- `WALK_UP`：向上直走到 `seatAnchor`（用背面走姿，背影）。
- `SETTLE`：播放"坐下"过渡 2 帧，然后切坐姿 idle。
- `LEAVING`：反向走完全程，出画后座位转 `EMPTY`。

### 3.2 触发来源（谁让谁进场）

| 事件 | 触发 |
|---|---|
| 当前会话首次 `agent/status → running` | 主 agent 从门外走入，坐主工位 |
| `subagent/start` / `workflow/agent-start` | 对应副座位入队，逐个走入 |
| `subagent/end` / `workflow/agent-end` | 该副座位走离场流程 |
| 切换会话 | 场景**重置**：清空所有座位 → 主角重新入场（不保留上个会话的人） |
| 会话结束 / 关闭 | 全员离场（不播，直接淡出，避免关页面还在演） |

### 3.3 排队调度（"同时分发多个要一个一个进来"）

**全局单通道入场队列**——任何时刻画面里最多只有 1 个人在走。

```
entranceQueue: string[]      // 座位 id 队列
walking: string | null       // 当前正在走的人
```

- 新 agent 到达 → push 到 `entranceQueue` 尾部 → 状态先置 `QUEUED`。
- `walking === null` 且队列非空 → 弹出队首，置 `walking`，开始 `ENTERING`。
- 该人走到 `SETTLE` 完成后，**停留 `gapMs` 再释放** `walking`，让下一个出发。`gapMs = 260ms`——这个停顿是关键，两人无缝衔接会看着像一段连续动画，停下来才读得出"这是下一个人"。
- 离场**不占**入场队列（走背景通道，允许与入场重叠）。但如果同一座位的离场还没结束就不能再入场，座位加 `occupiedUntil` 时间戳。
- **队列积压兜底**：若 `entranceQueue.length > 6`，后面的跳过行走动画，直接在座位上做 4 帧淡入（`opacity 0→1`），避免用户等 15 秒才看到人。

### 3.4 路径与时序

走速 **48 px/s**（逻辑像素），走路帧 4 帧循环 **120ms/帧**（≈8.3 帧/秒）。

按 320×480 场景估算：

| 路线 | 距离 | 时长 |
|---|---|---|
| 门外 → 入画 | 16 px | 0.3 s |
| 入画 → 主工位 lane（居中） | ~40 px | 0.8 s |
| 沿 lane 上走到主座位 y=168 | ~300 px | 6.3 s |
| 坐下过渡 | — | 0.25 s |
| **主 agent 从门到落座** | — | **约 7.6 s** |

7.6 秒太慢了，用户发完消息要盯着看 7 秒才见鱼坐下。三条调整（可叠加）：

1. **入口上移**：门不在 y=492（画面外），而是画面内下沿留一条"门口台阶"y≈440，角色从 440 起步 → 主工位距离缩短到 ~270 px。
2. **主角走快**：主 agent 速度 72 px/s（比副角快，主角更有精神），副角 48 px/s。
3. **首帧即有反馈**：`turn/start` 一收到就让工位亮灯（桌上屏幕点亮 + 工牌变绿），**人还在走**，用户已经知道"接活了"。这一条最重要——动画是氛围，不承载状态传达。

推荐组合：1+2+3。主 agent 实际落座约 **3.8 s**，副角约 **5 s**，但状态灯是 0 延迟的。

### 3.5 帧表清单（入场部分）

| 名字 | 帧数 | 用途 |
|---|---|---|
| `walk-up-a/b/c/d` | 4 | 向上走（背影），循环 |
| `walk-down-a/b/c/d` | 4 | 向下走（正面），循环 |
| `walk-side-a/b/c/d` | 4 | 横向走，左右用镜像 |
| `sit-down-1/2` | 2 | 站 → 坐 过渡 |
| `stand-up-1/2` | 2 | 坐 → 站 过渡 |

共 16 帧 × 2 个尺寸（主 32 / 副 24）= 32 张图。这是 §1.6 之外的增量。

## 4. 环境动态层（底图是死的，场景得活）

底图是一张静态像素画。所有"活"的东西都靠**在底图上叠一层动态贴图**实现，底图本身一个像素都不改。

统一的四条原则：

1. **底图画"最安静的状态"**——屏幕息屏、灯灭时、钟面指针归零位。动态层负责把东西"点亮/推动"。
2. **动态层是独立的 canvas 图层**，绘制在底图之上，位置全部从 `seats.json` / `scene.json` 的锚点推算，不靠肉眼对坐标。
3. **不用 DOM，不用 GIF**——都在同一个 canvas 里二次绘制。像素对齐更稳，且能跟随时钟/状态实时变。
4. **动画不占 CPU**：全部由 `requestAnimationFrame` 单循环驱动，页面不可见时暂停。

### 4.1 屏幕亮灭状态机

**用户需求（原话）：「办公室电脑本来是息屏，工位有人坐下才会打开」**

底图里所有显示器都是**息屏状态**（深色近黑 #10141f ~ #171c28，只有极弱斜向反光，零发光）。屏幕亮起来完全是动态层画上去的。

| 座位状态 | 屏幕表现 |
|---|---|
| `EMPTY`（空位） | 底图原样：全黑，无叠加 |
| `ENTERING` / `WALK_LANE` / `WALK_UP`（人还在走） | 仍是黑屏。**灯先亮、屏后亮**——屏要等人真的坐下（`SETTLE` 完成）才亮 |
| `SEATED_IDLE` | 屏幕亮起，但只显示一个静态暗屏底 + 左上角 1px 光标闪烁 |
| `WORKING` | 亮屏 + `亮条上滚` 2~4 帧循环，帧率跟随打字帧率（140ms/帧） |
| `REPORTING` | 亮屏 + 亮条滚动减速（280ms/帧），表示在写汇报 |
| `IDLE`（坐着但没活） | 亮屏 + 光标缓慢闪烁，不滚动 |
| `LEAVING` 之后 | 屏幕在 300ms 内**亮度衰减到黑**（不是瞬切），人走了屏才灭 |

**开机/关机过渡**（别做瞬切，瞬切很廉价）：
- 开机 3 帧：`黑` → `横向一条 1px 亮线展开` → `全亮`（每帧 33ms，共 100ms）
- 关机 3 帧：反过来

屏幕在底图上的精确矩形从 `seats.json` 的 `deskAnchor` + 每工位固定偏移推算：主工位双屏两块（各约 28×14 逻辑 px），副工位单屏一块（约 14×9 逻辑 px）。

亮屏的色值只用三个：底光 `#0b1424`、扫描亮条 `#4fd6bb`、高光 `#b8fff0`。不再多。

### 4.2 灯光闪烁

**用户需求（原话）：「灯会闪烁」**

底图里两盏吊灯是静态的暖黄光晕。动态层负责让它们"活着"，但**闪烁必须是微妙的氛围，不能是故障**——办公室不该像恐怖片。

- 每盏灯维护一个**双正弦叠加**的亮度因子：`k = 0.94 + 0.045*sin(t*w1+φ1) + 0.015*sin(t*w2+φ2)`
  - 慢波 `w1` 周期 5.5±1.2s（呼吸感），快波 `w2` 周期 0.7±0.3s（细微抖动）
  - 两盏灯 `φ` 不同（错开相位），避免同频闪烁显得假
- 亮度因子只作用于**光晕**的 alpha，不作用于灯罩本体——灯罩是实体，不能抖
- 光晕分 3 圈绘制（`lampHi` → `lamp` → `lampLo`，alpha 递减），每圈乘同一个 `k`
- **极低概率事件**（每 40~90s 触发一次，持续 120ms）：单盏灯瞬间掉到 `k*0.72` 再回升，模拟"灯管接触不良"。这个偶发才有味道，但不能频繁
- 有人 `WORKING` 时，该工位区的灯光 `k` 平均上调 4%（人多气场足），幅度要小到说不清是不是错觉

**不做**：不做整间屋子忽明忽暗、不做灯灭掉、不做彩色灯。氛围灯只在吊灯上。

### 4.3 挂钟走针

**用户需求（原话）：「时钟会转」**

底图上墙正中有一个挂钟。动态层在上面画三根指针。

- 钟面中心与半径写死在 `scene.json` 的 `clock: {cx, cy, r}`
- 三根指针：时针（长 0.5r，2px 宽，`ink` 色）、分针（长 0.72r，1px 宽，`ink`）、秒针（长 0.8r，1px 宽，**`carpet` 暗红**，唯一有色那根，让"在走"这件事被眼睛抓住）
- **秒针每秒跳一格，不做连续扫**——像素画里连续扫会糊成一团抖动，跳格才干净。这是像素画特有的取舍
- 时针/分针按真实时间算，**不加倍速**。理由：这是个办公室，钟要是走得比现实快，看着会分心
- 走针角度：`θ = (value/max)*2π - π/2`（12 点朝上）。绘制用整数化端点 `round()`，保证像素对齐
- 钟心画一个 2×2 的 `ink` 圆点盖住三针根部

### 4.4 其它可选氛围（P11 之后做，不进主线）

| 元素 | 做法 | 优先级 |
|---|---|---|
| 窗外夜空星星微闪 | 窗玻璃区域叠 3~5 个 1px 白点，各自独立 6~11s 周期呼吸 | 低 |
| 绿植轻微摆动 | 整块 sprite 左右平移 1px，周期 4.5s，只在有人 WORKING 时动 | 低 |
| 咖啡机冒热气 | 3 个 1px 灰白点向上飘 4 帧 | 低 |
| 白板内容 | 有人 WORKING 时随机出现 2~3 个短横线当"字" | 低 |

### 4.5 性能预算

单帧最多这么多绘制调用，超了就说明写歪了：

| 图层 | 单帧 draw 上限 | 说明 |
|---|---|---|
| 底图 | 1 | `drawImage` 整张贴图，不重绘 |
| 屏幕 | ≤ 13 | 主工位 2 + 副工位 12，只画亮的那些 |
| 光晕 | ≤ 6 | 2 盏灯 × 3 圈 |
| 挂钟 | ≤ 5 | 3 针 + 钟心 + 钟面遮蔽 |
| 角色 | ≤ 14 | 主 1 + 副 12 + 余量 |
| 气泡锚点 | ≤ 13 | 真气泡是 DOM，这里只留定位 |

合计 **< 60 draw/frame**，60fps 毫无压力。任何一项超了都是 bug，不是"正常开销"。

**不做的事**：不用 DOM 里真的跑一个终端；不用 GIF（色深差、没法跟状态联动）；不用 CSS 动画做像素位移（会亚像素化，糊）。

## 5. 数据结构

Host 侧聚合出快照，Client 轮询拿：

```ts
interface OfficeSnapshot {
  seq: number;
  sessionId: string;
  scene: 'idle' | 'running';
  main: SeatState | null;
  subs: SeatState[];          // 长度 = 12，null 表示空位
}

interface SeatState {
  seatId: string;             // 'main' | 'sub:0' ... 'sub:11'
  agentId: string;            // 稳定标识，用于前端判定"这是不是同一个人"
  label: string;              // 显示名
  model: string;              // 决定装扮
  provider: string;
  activity: 'queued' | 'working' | 'idle' | 'done' | 'error';
  bubble: BubbleState;
  files: DeliverableRef[];
  progress?: { done: number; total: number } | null;
}

interface BubbleState {
  text: string;               // 最近一条 assistant 文本，截断到 240 字
  streaming: boolean;
  updatedAt: number;          // 用于判断气泡该不该自动收起
}

interface DeliverableRef {
  path: string;               // 相对工作区
  name: string;
  kind: 'file' | 'image' | 'doc';
}
```

**关键**：`seatId` 是稳定坐标，`agentId` 是临时身份。前端靠 `agentId` 变化判断"换人了"→ 触发出场/入场动画。同一个 `seatId` 上 `agentId` 从 A 变 B，就是 A 离场 B 入场（走队列）。

**动画不进 Host**：Host 只输出"当前谁在哪个座位"。入场队列、行走插值、帧选择全在 Client。这样 Host 不需要知道 120ms 帧率，也不用为动画维护定时器。

## 7. 已知风险

| 风险 | 影响 | 应对 |
|---|---|---|
| AI sprite sheet 格子对不齐 | 姿态基准废掉，退回逐张生成，一致性变差 | 允许 3 次重试；失败降级并记录 |
| 跨次生成形象漂移 | 动画里角色"变脸" | 参考图链 + 每帧眼看验收；宁可少做几帧也不放松 |
| 抠色吃掉深色描边 | 角色边缘发虚 | 阈值可调 + 后补 1px 描边开关 |
| 底图屏幕与动态贴图对不齐 | 屏幕上出现错位色块 | 锚点精确标定；贴图区留 1px 内缩 |
| client `inject` 写了不存在的服务 | **整个 web boot 失败**（本机已发生过两次） | inject 只列确定存在的：`slots` `locale` `sessions`；避开 `configForms` |
| 入队队列过久 | 用户等 15 秒看不到人 | 积压 > 6 走淡入兜底 |
| 12 副席在 320 宽里太挤 | 椅子/人重叠 | P0 阶段先验证布局，挤就降到 8 席 |
| 底图画了亮屏，动态层没法演"开机" | 屏幕亮灭需求做不出来 | 底图必须画最安静态（全息屏）；已重出 `room-dark-01.png`（§4.1） |
| 灯光闪烁过度像故障 | 氛围变恐怖片 | 双正弦叠加，幅度 ≤5%；掉电事件 40~90s 一次、仅 120ms（§4.2） |
| 挂钟秒针连续扫 | 像素画里糊成抖动团 | 秒针**跳格**不扫秒；三针端点全部 `round()`（§4.3） |
| 秒针每帧重绘但角度没变 | 白烧 CPU | 角度变了才重绘（秒针 1Hz，分针 1/60Hz，时针极少） |
